# @coraxjs/core 0.1.1

## History loading

- Bundle the official SQLite Local World from `vercel/workflow` commit
  `c11fc40013681fef9afe0b315b1d22284579bbe0` (upstream PR #5235).
  Stream tail and cursor reads use indexed database queries instead of opening
  every historical chunk file. No 32-way filesystem scan patch is included.
- Share one fixed tail boundary within each finite HTTP history request,
  including when Nitro and the Workflow runtime load separate module copies.
- Avoid an unnecessary tail lookup for positive-cursor live subscriptions while
  preserving early rejection of missing or expired sessions.
- Release orphaned local steps before re-enqueueing retained development runs.

## Local storage

The native Local World now stores runs, events and streams in
`<CORAX_DATA_DIR>/.workflow-data/world.db`, using Node's built-in SQLite driver.
The usual project-local default is `.corax/.workflow-data/world.db`.
Existing file-layout runs are not migrated or listed by this implementation;
their files are left untouched. New sessions use SQLite.

Corax keeps the 0.1.x public API, v26 message stream and Workflow spec 8 default.
Node.js 24+ remains required. The pinned upstream sources and their checksums are
included in the source repository; published packages contain the bundled
implementation, license and provenance without a new native addon dependency.

See [history-read-maintenance.md](../history-read-maintenance.md) for provenance,
build inputs, validation and benchmark boundaries.
